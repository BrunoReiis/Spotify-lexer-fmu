FOCO: EXERCÍCIO 7 — OPÇÃO 5: COMANDOS DE PLAYLIST (SPOTIFY)

1. OBJETIVO
A aula ensina a construir um analisador léxico usando Python, Lark, Regex, Jupyter Notebook e ipywidgets.
O lexer transforma texto em tokens. Ele identifica e classifica partes do texto, mas não valida a sintaxe completa.

Exemplo:
PLAYLIST "Treino"
ADICIONAR "Nome da faixa"
DURACAO 03:45 GENERO rock
ORDENAR popularidade

2. CONCEITOS
TOKEN = categoria lógica, como PLAYLIST, DURACAO ou GENERO.
LEXEMA = texto real encontrado, como "Treino".
PADRÃO = regra/Regex que determina o que pertence ao token.

3. REGRAS IMPORTANTES
MAXIMAL MUNCH:
O lexer tenta reconhecer o maior pedaço possível.

PRIORIDADE:
Quando dois tokens podem reconhecer o mesmo trecho, a prioridade determina qual vence.
Exemplo da aula: R$ 25,90 pode começar como um identificador R, enquanto PRECO reconhece o valor inteiro. Por isso PRECO pode receber prioridade maior, como PRECO.2.

ERRO LÉXICO:
Quando nenhum token reconhece o caractere atual, o Lark gera UnexpectedCharacters.
O erro possui line, column e char.

4. REGEX IMPORTANTES
\d = um dígito
\d+ = um ou mais dígitos
\d{2} = exatamente dois dígitos
\d{1,3} = de 1 a 3 dígitos
[A-Z] = uma letra maiúscula
[A-Z0-9]* = zero ou mais letras maiúsculas ou números
"[^"\n]*" = texto entre aspas
\b = fronteira de palavra
/i = case-insensitive

Exemplo:
 /pix\b/i
reconhece pix, PIX, Pix etc.

5. LARK
from lark import Lark
from lark.exceptions import UnexpectedCharacters

lexer = Lark(
    gramatica,
    parser="lalr",
    lexer="basic"
)

tokens = list(lexer.lex(texto))

Cada token possui:
t.type
t.value
t.line
t.column
t.start_pos
t.end_pos

6. IGNORAR ESPAÇOS E COMENTÁRIOS
Espaços, tabs e quebras:
%ignore /[ \t\r\n]+/

Comentários:
COMENTARIO: /#[^\n]*/
%ignore COMENTARIO

7. EXEMPLOS DA AULA
CENÁRIO A — DELIVERY:

Tokens incluem PEDIDO, ENTREGA, CUPOM, QTD, ITEM, PRECO e CODIGO.

CENÁRIO B — PIX:
Exemplos: maria@gmail.com, 123.456.789-09, +5511987654321 e UUID.
Tokens incluem CHAVE_EMAIL, CHAVE_CPF, CHAVE_TELEFONE e CHAVE_ALEATORIA.
Também existem PIX, ENVIADO, RECEBIDO, PARA, DE, EM, VALOR, DATA e HORA.

8. CONFLITO DE PRIORIDADE DO PIX
Para:
pix@loja.com.br

/pix\b/i pode reconhecer "pix" como PIX, mas o texto inteiro é um e-mail.
Por isso CHAVE_EMAIL recebe prioridade maior:
CHAVE_EMAIL.4
Palavras reservadas: prioridade 3.
Literais/outras chaves: prioridade 2.

Esse é um exemplo de ambiguidade léxica e deve ser explicado.

1) Tabela documentada de tokens com:
- token
- descrição

- exemplo

Exemplo:

4) Pelo menos 3 literais definidos por Regex.

5) Pelo menos 1 conflito de prioridade identificado, resolvido e explicado.

- qual era o conflito
- quais tokens competiam
- qual recebeu prioridade
- por que funciona

- linha
- coluna
- caractere

- texto colorido
- tabela de tokens

9) Pelo menos 3 entradas válidas e 2 inválidas.

14. ERROS
Exemplo:
PLAYLIST "Treino

Dica:
Nomes de playlists e músicas devem estar entre aspas.

Outro:
DURACAO 3:4

Se a Regex exigir MM:SS:
Dica: use o formato MM:SS, por exemplo 03:45.

15. O QUE NÃO FAZER
O lexer não precisa validar a sintaxe completa.
Por exemplo:
PLAYLIST "Treino"
ADICIONAR "Musica"

O lexer identifica:
PLAYLIST
TEXTO
ADICIONAR
TEXTO

A verificação da ordem correta pertence a uma etapa posterior.

16. O QUE O ALUNO DEVE CONSEGUIR EXPLICAR
É necessário explicar cada Regex e cada prioridade usada.
Exemplo:
/\d{2}:\d{2}/
\d = dígito
{2} = exatamente duas ocorrências
: = dois-pontos literal

A atividade informa que, mesmo usando IA, o aluno deve ser capaz de explicar cada Regex e prioridade.
